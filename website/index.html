Read-only first

Operational context without hidden write authority.

Manager normalizes approved visibility from specialized systems and fails soft when an integration is unavailable or malformed. It does not turn monitoring access into administrative authority.

01

Network context

NetBird peer visibility uses a read-only path and preserves NetBird as the authority for network control.

02

Service + job health

Uptime Kuma and Healthchecks provide bounded monitoring signals without importing their management authority.

03

Resource visibility

Beszel data enters through a delegated, sanitized artifact rather than broad credentials or the Docker socket.

04

Protection context

Kopia visibility uses a delegated status artifact; backup state is not presented as proof that a restore will succeed.

05

Operational work

GoreeCloud Tasks remains authoritative for task content and authorization while Manager receives only approved operational fields.

06

Fail-soft presentation

Disabled, stale, unreachable, rejected, or malformed integrations degrade visibly without fabricating values or breaking the entire overview.

Control-plane discipline

Visibility is useful only when the boundaries stay legible.

Private by default

No direct public backend exposure. The public site stays separate from the private Manager runtime.

Least privilege

Read-only or delegated integration paths are preferred; Manager does not require a direct Docker socket.

Truthful state

Unavailable evidence is shown as unavailable. Monitoring signals are not promoted into guarantees they cannot prove.

Specialized authority

Network, monitoring, backup, tasks, Identity, Wardveil Security, Privacy Shield, and Everkeep keep their own authoritative responsibilities.

Privacy-respecting UI

No analytics, trackers, third-party browser scripts, or remote font delivery are required by this public website.

Recovery before dependency

Backup and recovery remain a prerequisite before Manager can become a production dependency.
